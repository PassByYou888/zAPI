## 💡 这是什么？

**zAPI** 是一个**跨语言、跨进程、跨机器的远程调用框架**，基于 C4 分布式服务网格构建。它让您可以用**任何语言**写服务端，用**任何语言**写客户端——它们之间可以无缝对话。

想象一下：

- 用 **Rust** 写核心计算服务，用 **Python** 写 AI 推理，用 **Go** 写网关——它们互相调用，就像在同一个进程里一样。
- 用 **Pascal** 写的遗留系统，零成本接入现代化微服务生态。
- 用 **C#** 写业务逻辑，用 **Java** 写数据处理，用 **C++** 写高性能模块——它们各司其职，又浑然一体。
- **v2.0 新增：** 用 **PHP** 或 **Node.js** 通过 HTTP 网关调用上述所有服务，**零原生依赖**。

**这不是 RPC 框架的又一个变体，而是一个让所有编程语言平等对话的分布式操作系统。**

## 🔥 应用场景（无限可能）

### 1. 微服务架构

用不同语言编写不同的微服务，通过 zAPI 统一通信。不再受限于单一技术栈。

### 2. 遗留系统现代化

把 20 年前的 Pascal/Delphi 系统，通过 zAPI 暴露为现代 API，与 Go、Rust 新服务无缝集成。

### 3. AI/ML 服务

用 Python 写模型推理服务，用 Rust/Go 写高性能网关，用 C# 写业务前端——各取所长。

### 4. 分布式计算

计算密集型任务用 C++/Rust 实现，调度和协调用 Go，数据分析用 Python——zAPI 让它们协同工作。

### 5. 游戏服务器

用 C++ 写核心引擎，用 C# 写业务逻辑，用 Python 写运维工具——一套框架全搞定。

### 6. 嵌入式与 IoT

轻量级 IPC 通信，适合资源受限的边缘设备。

### 7. 跨团队协作

前端团队用 C#/Java，后端团队用 Rust/Go，算法团队用 Python——各团队用自己最擅长的语言，zAPI 负责让它们对话。

### 8. 云原生

支持 TCP 跨机通信，天然适配容器化和 Kubernetes 环境。

### 9. v2.0 新增：热更新与动态治理

使用 `API_UnReg` 动态注销旧 API，重新注册新 API，**实现不停机更新**。使用 `API_SetOption` 动态调整配置，无需重启。

## 📦 快速上手

### 第一步：获取动态库

从 [Releases](https://github.com/PassByYou888/zAPI/releases) 下载对应平台的动态库：

| 平台 | 文件 |
| :--- | :--- |
| Windows 64-bit | `z_api_hub64.dll` + `z_ipc_64.dll` |
| Windows 32-bit | `z_api_hub32.dll` + `z_ipc_32.dll` |
| Linux / BSD | `libz_api_hub.so` + `libz_ipc.so` |
| macOS | `libz_api_hub.dylib` + `libz_ipc.dylib` |

### 第二步：写一个服务端（以 Rust 为例）

```rust
use api_hub_rust::*;

extern "C" fn add_callback(_trigger: *mut c_void, input: DataHnd, output: DataHnd) {
    let mut h = unsafe { DataHandle::from_raw(input) };
    let a = h.read_i32().unwrap_or(0);
    let b = h.read_i32().unwrap_or(0);
    let sum = a + b;
    let _ = write_buffer(output, &sum.to_le_bytes());
    println!("add({}, {}) = {}", a, b, sum);
}

fn main() -> Result<()> {
    let app = AppHandle::new("CalcService", "Calculator")?;
    app.register_call("add", "a+b", std::ptr::null_mut(), add_callback)?;

    // v2.0 新增：运行时配置
    set_option("Wait_Connection_ReadyOk", "False");

    reset_prepare();
    prepare_service("0.0.0.0:9898", "127.0.0.1:9898")?;
    prepare_client("127.0.0.1:9898", app.as_raw())?;
    prepare_done()?;

    println!("服务已启动，按 Enter 退出...");
    let _ = std::io::stdin().read_line(&mut String::new());

    // v2.0 新增：动态注销 API
    app.unregister("add")?;

    exit_main_thread();
    shutdown();
    Ok(())
}
```

### 第三步：写一个客户端（以 Python 为例）

```python
from api_hub import C4

# 远程调用 Rust 写的计算服务
client = C4("CalcService", "127.0.0.1:9898")
result = client.add(10, 20)
print(f"10 + 20 = {result}")
```

### 第四步：或者用 PHP 客户端（v2.0 新增）

```php
<?php
require_once 'ZAPIBridgeClient.php';
$client = new ZAPIBridgeClient('http://127.0.0.1:8080/v1');
$result = $client->invoke('CalcService', 'add', [10, 20]);
echo "10 + 20 = " . $result . "\n";
?>
```

就这么简单。**Rust 写的服务，Python 和 PHP 直接调用**——跨语言、跨进程、跨机器。

## 🛠️ 技术亮点

### 1. 真正的线程安全

除状态日志函数外，所有 API 均可从任意线程并发调用，无需外部加锁。

### 2. 回调线程池执行

所有回调在后台线程池中执行，最大化吞吐量。但同时要求回调**不能阻塞、不能递归调用**，避免死锁。

### 3. 零拷贝数据访问

`API_GetBuffer` 提供直接内存访问，无需复制数据。

### 4. 自动服务注册

客户端连接后自动注册应用，断线自动重连并重新注册。

### 5. 负载均衡

同一应用名可在多个进程注册，C4 自动将请求分发到负载最低的实例。

### 6. v2.0 新增：动态服务治理

- `API_UnReg` 支持运行时移除 API，适合热更新、灰度发布、权限动态调整。
- `API_SetOption` 支持运行时调整认证密码、等待连接行为、IPC 线程池大小等。

### 7. v2.0 新增：PHP/Node.js 支持

通过 ZAPI Bridge HTTP 网关，PHP 和 Node.js 可以双向调用任意 zAPI 服务，零原生依赖。
