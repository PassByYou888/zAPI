## 1. 概述：API Hub 是什么

API Hub 是一个**基于 C4 分布式服务网格的轻量级 RPC 框架**，它通过一组纯 C 函数（ABI）让不同语言、不同进程、不同机器之间能够**像调用本地函数一样**进行通信。

- **核心 C 动态库**：`z_api_hub64.dll` / `libz_api_hub.so` / `libz_api_hub.dylib`，导出约 20 个 API。
- **Pascal 绑定**：`z_api_hubtool_import.pas` —— 这是**所有语言绑定的参考实现**，我们 Python 绑定完全遵循其语义。
- **Python 绑定**：基于 `ctypes` 封装，提供 `DataHandle`、`App`、`Server`、`C4` 等 RAII 类，让 Python 开发者无痛接入。

**核心价值**：  
- ✅ 将任意 Python 函数暴露为远程 API，供 C++/Go/Java/Rust/C#/PHP/Node.js 等语言调用。  
- ✅ 用 Python 透明地调用其他语言编写的服务，无需 HTTP、不写 IDL、无需生成桩代码。  
- ✅ 自动处理服务发现、负载均衡、断线重连、NAT 穿透。  
- ✅ **新增**动态注销 API（`App.unregister()`）和运行时配置（`set_option()`）。

## 2. 核心概念（必读）

在深入代码前，请先理解以下概念，它们与 Pascal 完全对应。

| 概念 | 说明 |
|------|------|
| **数据句柄（DataHandle / TDataHnd）** | 封装一个 **API 名称** 和一段 **二进制载荷**。所有输入参数和输出结果都通过它传递。API 名称在创建时固定，后续读写只影响载荷。 |
| **应用句柄（App / TAppHnd）** | 代表一个逻辑应用，可注册多个 API（Call 或 Notify），在网络中具有唯一名称。客户端通过 `应用名 + API 名` 路由请求。 |
| **Call（请求-响应）** | 同步调用，发送请求并等待响应。对应 `API_Call` 函数。 |
| **Notify（单向通知）** | 异步通知，不等待响应。对应 `API_Notify` 函数。 |
| **回调（Callback）** | 服务端注册的函数，当远程调用到达时执行。**所有回调都在后台线程池中运行**（非主线程），因此必须遵守线程安全规则（见第 12 节）。 |
| **动态注销** | 运行时移除已注册的 API，触发网络广播（约 3 秒传播）。 |
| **运行时配置** | 动态调整全局参数（密码、等待连接、IPC 线程池等）。 |
| **线程安全** | 所有 API 均可并发调用。但单个 DataHandle 的写操作需串行化。 |

## 4. 快速入门 —— 三分钟跑通第一个服务

### 4.1 编写一个简单的加法服务（server.py）

```python
from api_hub import Server

app = Server("CalcService")

@app.expose("add")
def add(a: int, b: int) -> int:
    return a + b

if __name__ == "__main__":
    app.start("ipc:calc_service")   # 使用 IPC（同机通信）
    input("服务运行中，按 Enter 停止...")
    app.stop()
```

### 4.2 编写客户端调用（client.py）

```python
from api_hub import C4

client = C4("CalcService", "ipc:calc_service")
result = client.add(10, 20)
print(f"10 + 20 = {result}")   # 应输出 30
C4.shutdown()
```

> **💡 解释**：  
> - `Server("CalcService")` 创建了一个逻辑应用，名称为 `"CalcService"`（区分大小写）。  
> - `@app.expose("add")` 将 `add` 函数注册为远程 API。  
> - `app.start("ipc:calc_service")` 启动服务，监听 IPC 通道 `calc_service`。  
> - 客户端 `C4("CalcService", "ipc:calc_service")` 连接到同一 IPC 通道，并准备调用应用 `CalcService`。  
> - `client.add(10, 20)` 自动序列化参数、发送请求、接收响应并反序列化结果。

## 5. 数据句柄（DataHandle）详解

`DataHandle` 是底层 `TDataHnd` 的 RAII 封装，负责管理 API 名称和二进制数据。

### 5.1 创建与释放

```python
from api_hub import DataHandle

# 创建句柄，API 名称为 "echo"
h = DataHandle("echo")
# 句柄内部初始载荷为空

# 显式释放（或使用 with 语句，或依赖垃圾回收）
h.free()
```

**重要**：  
- `DataHandle` 在 `__del__` 中会自动释放，但建议显式 `free()` 或使用上下文管理器。  
- 从 `API_Call` 返回的句柄同样需要释放（即使其大小为 0）。

### 5.2 写入数据

```python
h = DataHandle("upload")
# 写入整数
h.write(12345)
# 写入字符串（自动编码为 UTF-8）
h.write("hello")
# 写入字节
h.write(b"world")
h.free()
```

`write()` 方法使用默认序列化器（JSON + pickle 回退），也可以传入自定义序列化器（见第 11 节）。

### 5.3 读取数据

```python
h = DataHandle("echo")
h.write({"key": "value"})   # 序列化为 JSON
data = h.read()             # 读取全部载荷（从位置 0 开始）
print(data)                 # 输出 {'key': 'value'}
h.free()
```

`read()` 会**重置当前位置到 0**，读取整个缓冲区，并尝试反序列化。

### 5.4 位置与大小

```python
h = DataHandle("test")
print(h.size)          # 当前缓冲区大小（字节）
h.write("abc")
print(h.size)          # 输出 3（假设序列化后为 3 字节）
# 位置操作（底层对应 API_GetPos / API_SetPos）
# 但通常不需要手动操作，因为 write/read 已管理位置
h.free()
```

### 5.5 底层访问（零拷贝）

如果需要直接操作原始字节，可以使用 `h.raw` 获取底层 ctypes 句柄，并配合 `_native` 模块中的 `API_GetBuffer`、`API_GetSize` 等函数。这适合高性能场景，但需小心内存越界。

## 6. 应用句柄（App）详解

`App` 封装了 `TAppHnd`，用于注册 API。

### 6.1 创建与释放

```python
from api_hub import App

app = App("MyApp", "This is my application")
# 注册 API...
app.free()   # 释放句柄，同时注销所有注册的 API
```

`App` 也支持 `with` 语句，自动释放。

### 6.2 注册 Call API（请求-响应）

```python
def my_add(trigger, inp, out):
    # trigger: 用户数据（注册时传入，此处用不到）
    # inp: DataHandle（只读），包含请求参数
    # out: DataHandle（只写），用于写入响应
    data = inp.read()        # 这里假设参数是一个列表 [a, b]
    a, b = data
    out.write(a + b)

app.register_call("add", my_add, "Addition API")
```

注意回调签名必须为 `(trigger, inp, out) -> None`，且**不能阻塞**（见第 12 节）。

### 6.3 注册 Notify API（单向通知）

```python
def my_logger(trigger, inp):
    msg = inp.read()
    print(f"Log: {msg}")

app.register_notify("log", my_logger, "Logger")
```

### 6.4 动态注销 API（新增）

`App.unregister()` 方法允许您在运行时移除已注册的 API。

```python
# 注册 API
app.register_call("add", my_add, "Addition")

# ... 运行一段时间后 ...

# 动态注销 'add' API
if app.unregister("add"):
    print("API 'add' unregistered, broadcast in progress.")
else:
    print("API 'add' not found.")
```

**关键行为**：
- **本地立即生效**：API 从本地注册表中同步删除。
- **网络异步广播**：删除操作触发 C4 服务网格广播，传播时间约 3 秒。
- **传播延迟窗口**：在广播传播期间，远程调用可能仍然到达并收到"未找到"错误。

**使用场景**：
- **热卸载插件**：动态库插件可先注销自身 API，再安全卸载。
- **临时维护模式**：临时下线某些功能 API，无需重启整个应用。
- **权限动态调整**：根据用户角色或运行时条件，移除敏感 API 暴露。

### 6.5 本地调用（无网络）

`App` 提供了 `local_call` 和 `local_notify`，用于在**同一进程内**测试 API 逻辑，避免启动网络层。

```python
param = DataHandle("add")
param.write([10, 20])
result = app.local_call(param)
print(result.read())   # 输出 30
param.free()
result.free()
```

## 7. 服务端（Server）—— 暴露 Python 函数

`Server` 类在 `App` 之上进一步简化，提供装饰器式注册并自动管理网络准备。

### 7.1 创建服务端

```python
from api_hub import Server

server = Server("MyService", "A demo service")
```

### 7.2 使用 `@expose` 注册 Call API

```python
@server.expose("echo")
def echo(msg: str) -> str:
    return f"Echo: {msg}"
```

默认情况下，`@expose` 注册为 **Call**（请求-响应）。装饰器会自动处理参数的序列化/反序列化，并捕获异常返回错误对象。

### 7.3 注册 Notify API

```python
@server.expose("log", notify=True)
def log(level: str, msg: str):
    print(f"[{level}] {msg}")
```

通知 API 无返回值，异常被忽略（符合通知语义）。

### 7.4 启动服务

```python
server.start("ipc:my_service")   # 也可以使用 TCP，如 "127.0.0.1:9898"
```

`start` 内部执行：
- `API_Reset_Prepare()`
- `API_Prepare_Service(addr, public_addr)`
- `API_Prepare_Client(addr, app.raw)` 以暴露本应用
- `API_Prepare_Done()`

### 7.5 停止服务

```python
server.stop()
```

按顺序调用 `API_Exit_MainThread`、`API_shutdown`，并释放 `App`。

## 8. 客户端（C4）—— 调用远程服务

`C4` 类提供动态代理，使远程调用如同本地方法。

### 8.1 初始化客户端

```python
from api_hub import C4

client = C4("TargetApp", "ipc:target_service", timeout=3000)
```

- `app_name`：要调用的远程应用名称。
- `endpoint`：服务地址（与服务端的 `PhysicsAddr_` 一致）。
- `timeout`：默认超时（毫秒），0 表示无限。

### 8.2 动态调用

```python
result = client.add(10, 20)   # 自动调用远程 API 'add'
```

`__getattr__` 拦截属性访问，返回一个闭包，该闭包将参数打包为 DataHandle，调用 `API_Call`，然后反序列化结果。

### 8.3 发送通知

```python
client.notify("log", "INFO", "Service started")
```

通知无返回值。

### 8.4 关闭客户端

```python
C4.shutdown()   # 全局关闭，释放网络资源
```

由于底层 C4 框架是进程单例，`C4.shutdown()` 是类方法，会停止整个网络层。

## 10. 运行时配置（新增）

`set_option()` 函数允许您在运行时动态调整 API Hub 框架的全局配置选项。

### 10.1 函数签名

```python
from api_hub import set_option

set_option("password", "my_secret_token")
```

### 10.2 支持的选项

| 选项键（主名） | 别名 | 值类型 | 说明 |
|---------------|------|--------|------|
| `password` | `passwd` | 字符串 | 设置 C4 P2PVM 认证令牌。**服务端和客户端必须匹配**。 |
| `Quiet` | — | 布尔 | 启用/禁用静默模式（`True`/`False`）。 |
| `External_Conf_Auto_Save` | `Conf_Auto_Save` | 布尔 | 程序退出时自动保存配置到 `.ini` 文件（默认 `True`）。 |
| `Wait_Connection_ReadyOk` | `Wait_API_Prepare_Done`、`WaitConnect`、`Wait_Ready` | 布尔 | 控制 `PrepareDone` 是否阻塞等待所有客户端连接就绪。 |
| `Wait_Connection_Timeout` | `Wait_TimeOut` | 整数（毫秒） | 最大等待时间，默认 `30000`。 |
| `ShowThreadID` | `ShowThread`、`Show_Thread` | 布尔 | 在日志中显示线程 ID。 |
| `ConsoleOutput` | `Console_Output` | 布尔 | 启用/禁用控制台日志输出。 |
| `IPC_Serv_ThreadCount` | `IPC_ThreadCount`、`IPC_Server_ThreadCount` | 整数 | IPC 服务线程池大小，默认 `4`。 |
| `IPC_Serv_MaxQueueLength` | `IPC_MaxQueueLength` | 整数 | IPC 消息队列最大长度，默认 `4096`。 |
| `IPC_Serv_MaxMsgSize` | `IPC_MaxMsgSize` | 整数（字节） | 单条 IPC 消息最大大小，默认 `32768`。 |

### 10.3 使用示例

```python
from api_hub import set_option

# 设置认证密码
set_option("password", "my_secret_token")

# 服务端不等待客户端就绪（适合大规模部署）
set_option("Wait_Connection_ReadyOk", "False")

# 提高 IPC 并发能力
set_option("IPC_Serv_ThreadCount", "8")

# 开启详细日志（调试时使用）
set_option("ConsoleOutput", "True")
set_option("ShowThreadID", "True")
```

## 11. 序列化与自定义载荷

默认序列化器（`default_serializer` / `default_deserializer`）先尝试 JSON，若失败则回退到 `pickle`。这保证了跨语言兼容性（JSON 是通用格式）与 Python 对象灵活性（pickle 回退）。

**自定义序列化**：  
- 在 `DataHandle(api_name, data, serializer)` 中传入 `serializer` 函数。  
- 在 `client = C4(..., serializer=my_ser, deserializer=my_des)` 中传入。  
- 在 `Server` 内部，读写使用固定的 JSON 格式（但可通过覆盖 `_write_json` / `_read_json` 来修改）。

**二进制载荷注意事项**：  
- 所有数据最终都是二进制字节流，框架不关心格式。  
- 序列化器负责将 Python 对象转换为 `bytes`，反序列化器负责还原。

## 12. 线程安全与回调约束（⚠️ 关键）

### 12.1 导出函数线程安全

- ✅ `API_Call`、`API_Notify`、`API_WriteBuffer`、`API_ReadBuffer`、`API_Prepare_*`、`API_shutdown` 等**全部**可被多线程并发调用。  
- ❌ 唯一例外：旧版 `get_status()` 函数**非线程安全**（但库日志已改为自动打印到控制台，此函数仅用于兼容性）。

### 12.2 回调执行上下文

你的回调函数（通过 `@expose` 或 `register_call`/`register_notify` 注册）**运行在底层 C4 线程池的工作线程中**，而不是主线程。

**因此必须遵守**：

- **禁止阻塞**：不要在回调中执行 `time.sleep`、等待锁、循环大量计算等耗时操作。  
- **禁止调用 API_Call / API_Notify**：否则可能死锁（因为回调线程可能已持有内部锁）。  
- **禁止直接操作 UI**：如需更新 GUI，请使用 `threading` 或 `queue` 将任务派发到主线程。  
- **推荐做法**：如果必须执行耗时任务或发起远程调用，将任务放入队列，由另一个专用线程异步处理，回调立即返回。

**示例（正确）**：

```python
import queue
import threading

task_queue = queue.Queue()

def background_worker():
    while True:
        task = task_queue.get()
        # 这里可以安全地调用 API_Call
        res = client.call(...)

# 启动后台线程
threading.Thread(target=background_worker, daemon=True).start()

@server.expose("process")
def process(data):
    task_queue.put(data)   # 快速返回
    return "accepted"
```

## 13. 日志与调试

库会在控制台自动输出详细的运行日志（包括连接状态、注册信息、错误原因）。你可以在 `<可执行文件名>.api-tool.ini` 配置文件中调整日志行为。

常见日志含义：

| 日志 | 含义 | 解决 |
|------|------|------|
| `bind address already in use` | 端口/IPC 名称被占用 | 更换地址或终止其他进程 |
| `no found app("XXX") api("YYY")` | 目标应用/API 不存在 | 检查名称大小写 |
| `timeout` | 调用超时 | 增加超时，检查网络 |

## 14. 高级主题

### 14.1 并发调用

由于所有 API 都是线程安全的，你可以轻松实现高并发：

```python
import threading

def call_add(client, a, b):
    return client.add(a, b)

threads = []
for i in range(100):
    t = threading.Thread(target=call_add, args=(client, i, i*2))
    threads.append(t)
    t.start()
for t in threads:
    t.join()
```

### 14.2 超时与重试

`API_Call` 的超时参数（毫秒）可在客户端初始化时设置，也可在调用时通过额外参数（暂未暴露，可自行扩展）。超时返回的句柄大小为 0，此时可重试。

### 14.3 多实例负载均衡

只需在**不同进程**中启动多个服务端，注册**相同的应用名**。客户端调用时，C4 会自动将请求分发到负载最低的实例。

- 每个服务端使用不同的监听地址（如不同的 IPC 名称或端口），但公布地址（`PhysicsAddr_`）应相同（例如都用 `ipc:calc_service` 或 `127.0.0.1:9898`）。  
- 对于 IPC，多个服务端不能共用同一个 IPC 名称，需使用不同名称（如 `ipc:calc_1`、`ipc:calc_2`），但客户端可连接到任意一个。

### 14.4 本地调用（无网络）

在开发测试阶段，可以使用 `App.local_call` 避免启动网络，快速验证逻辑（参见第 6.5 节）。

## 16. 常见问题与排错

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| `ImportError` 或动态库加载失败 | 库文件不在搜索路径 | 将 `z_api_hub64.dll` 等放在 `api_hub` 目录或系统 PATH |
| `API_Prepare_Done` 返回 0（Server.start 失败） | 地址已被占用或格式错误 | 检查地址，查看控制台输出获取详细错误 |
| 回调未触发 | 应用名或 API 名大小写不一致 | 核对大小写，服务端与客户端完全一致 |
| 远程调用超时 | 网络延迟或服务端未响应 | 增加超时时间，检查服务是否正常运行 |
| 内存泄漏 | 未释放 DataHandle | 确保每个句柄都调用了 `free()` 或使用上下文管理器 |
| 回调中调用 API_Call 导致死锁 | 违反了回调约束 | 将远程调用移至后台线程 |
| 动态注销后仍有调用 | 广播传播延迟（约 3 秒） | 正常行为，等待广播完成即可 |
